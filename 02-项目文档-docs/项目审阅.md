## 需要优先修改

1. **P1：本地模拟入口被另一条规则阻塞。** `02-项目文档-docs/TRADING-STRATEGY.zh-CN.md:42` 允许本地模拟，`:16` 和 `:125` 又要求 Binance 股票权限。英文版本也有相同冲突。建议将本地股票模拟的数据和账本条件，与币安账户能力分开验证；选择本地模拟时不应依赖 Binance 股票交易权限。

2. **P1：API 连通与股票数据就绪缺少明确区分。** `04-运行状态-state/readiness.json:12` 起的股票验证项均为 false，当前文件夹没有已验证的股票行情来源。参考 PDF 的 Alpaca 接口不能靠替换平台名称迁移到 Binance。此次增加的脚本只核验 Spot 账户读取，不宣称已接通股票/ETF，也不会将币安里的加密资产当成美股。依据：[币安 Spot 账户查询文档](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/account-endpoints)。

3. **P1：止损规则没有可重放的成交模型。** `02-项目文档-docs/TRADING-STRATEGY.zh-CN.md:58` 要求触价止损，但 `03-定时任务-routines/schedule.json` 只列六个离散检查时点；`05-交易记录-data/current-state.json` 仅有初始资金和空仓。缺少两次检查之间的 OHLC 数据处理、跳空滑点、费用及同一根 K 线先触止损还是目标的规则。不能把检查时看到的价格当成真实止损成交。建议先补本地模拟成交与费用规则，再启动有持仓的实验。

4. **P2：日程尚不是可验证的运行机制。** `05-交易记录-data/current-state.json:4` 的起止日期为 null，交易日序号为 0。日程 JSON 本身不会触发任务，目录内没有调度注册、执行器或实际触发记录。此次未检查应用外部是否已有自动化，也未创建新定时任务。需要核验七个真实交易日、节假日和提前收盘，并确认调度指向此桌面目录。

5. **P2：状态可靠性仅有文字规则。** `03-定时任务-routines/CONTINUITY.md` 要求拦截重复或中断运行，但没有 run_id、锁、进行中标记及恢复程序。readiness 也未定义检查有效期。建议明确各类数据的过期标准，并实现重复执行和中断恢复，避免两次任务重复记账。

6. **P2：2 USDT 仓位缺少精度约定。** `02-项目文档-docs/TRADING-STRATEGY.zh-CN.md:77` 将单仓限制为 2 USDT，但没有约定碎股数量精度、最小名义金额、手续费或 USD/USDT 换算。建议保留风险上限，先定义本地模拟账本的 Decimal 精度、费用和汇率来源；不能为了产生交易记录擅自提高额度。

7. **P3：中英文内容各有两份，容易不一致。** AGENTS 的启动读取要求已经不同，schedule 也有两个完整副本。建议确定机器读取的唯一主文件，其余文件只作翻译说明，并加入一致性校验。
